# eks-gitops-config

**Config repository** for Project 4 of my DevOps portfolio — the **GitOps source
of truth** for three FastAPI microservices running on Amazon EKS.

Argo CD runs *inside* the cluster and continuously reconciles the cluster to
match this repo. Nothing is deployed by pushing from CI; everything is deployed
by Argo CD **pulling** from here.

| Repo | Role |
|------|------|
| [`eks-gitops-app`](https://github.com/fuhchu/eks-gitops-app) | Application source. CI builds/pushes images and **commits new image tags here**. |
| **`eks-gitops-config`** (this repo) | Helm charts + Argo CD `Application`s. Argo CD watches this repo and reconciles the cluster. |

## Layout

```
charts/        Helm charts Argo CD renders (postgres + 3 services)
apps/          one Argo CD Application per workload  (app-of-apps children)
bootstrap/     app-of-apps root + one-time cluster manifests
infra/         Terraform: EKS cluster, ECR, IRSA, ACM, addons, Argo CD install
```

## Who owns what

- **Terraform (`infra/`)** provisions the cluster, ECR, IRSA roles, the ACM
  cert, the IAM-bound addons (EBS CSI, AWS Load Balancer Controller, External
  Secrets Operator), and installs **Argo CD** itself. These must exist before
  Argo CD can pull secrets or provision an ALB — you can't GitOps the thing that
  does GitOps.
- **Argo CD (`apps/` + `charts/`)** owns everything in-cluster after bootstrap:
  postgres and the three services today, observability (Prometheus/Grafana) next.

## Sync model

`bootstrap/root-app.yaml` is an app-of-apps root that points at `apps/`. Syncing
it creates one child `Application` per workload, each rendering its chart in
`charts/`. **Sync-waves** bring postgres up before the services that depend on
it. Every Application uses automated sync with **prune** and **self-heal**, so
manual drift in the cluster is reverted back to what's in git.

## Secrets

No secret material lives in this repo. The Postgres password is generated by
Terraform into AWS Secrets Manager (`eks-gitops/postgres`); External Secrets
Operator pulls it via IRSA into native Kubernetes Secrets that the pods consume.
